## Goal and exact trust boundaries

The C4-C1 managed same-instance `Accelerator.load_state` intercepts and refuses **all** original Load delegation, including a claimed matching Fresh Step-1 path. C4-C2 must introduce a *separate authority* before allowing original pre-load hooks to execute, without relaxing any of those protections.

1. **Worker-supplied data are never proof.** `manifest["fresh_checkpoint_dir"]`, CLI `--resume`, `expected_resume_checkpoint_id`, the real on-disk progress `checkpoint_id`, and a Worker-provided `{"status": "physical_binding_valid"}` must NEVER independently permit Load.
2. **Runner-only acceptance authority.** A real independent Runner first checks actual Fresh physical Step-1 evidence outside the Worker: correct Case/Source/Run/Phase, fixed SD3.5 Medium reference manifest and policy/input identity, real original C4-B Step-1 LoRA writer + external safetensors, all original nine Accelerate+SD3 files and hashes, real Fresh checkpoint ID, physical Step-1 timeline and full 263-target/526 BF16 trained Parameter +263 BF16 Alpha = 789 Tensor relationship. Runner acceptance is distinct from a Worker result and from Host metadata timeline validity. The Worker cannot mint a trusted capability by constructing a Python dict, supplying a copied SHA, writing a JSON receipt or claiming a Runner PID/name. If a protected Runner-to-Worker attestation / IPC credential cannot yet be established, remain **fail-closed**.
3. **Race-safe pre-Load revalidation.** Just before calling the real original `Accelerator.load_state`, require the authority-verified original Fresh parent path inside the fixed work_root, no symlinks/reparse aliases, the exact unchanged nine original files and their trusted hashes, unchanged separate external LoRA file, actual checkpoint ID and source/policy/phase bindings. A second check after original Load may be needed to detect mutation during read; do not use Worker-recomputed hashes as the reference.
4. **Original delegation exactly once.** Only after the above preflight may `C4StepAdapter` call its frozen class-defined original bound method on the **same prepared Accelerator**, with the production original input path/args and original registered Model/Policy/SD3 Load hooks unchanged. Consume the one-shot attempt before delegation; failures, partial original restore and exceptions never re-open admission. Preserve original exception and roll back instance wrapper slots in `finally`.
5. **Load returned is not qualification.** Accelerate 1.6.0 may log `Could not load random states` and return successfully. C4-C3 must separately verify post-Load actual BF16 trainable/Alpha, Model, Muon/AdamW Child Optimizers, Composite Scheduler, **actual restored RNG**, Epoch/SD3 cursor and parent identity against accepted original disk bytes. No `checkpoint_loaded` event or C4-A Resume Step-2 anchor until C4-C3/C4-C4. C4-D, independent Fix D, true R1/R2 CUDA and `worker_complete` remain blocked.
6. **No CPU counterfeit admission.** The real pinned CPU Accelerate Save/Load diagnostic has only four files. It proves original mechanics but cannot become a production nine-file accepted parent. Pure Host tests never unpickle RNG/model/optimizer or grant CUDA status.
